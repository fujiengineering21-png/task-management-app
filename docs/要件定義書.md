# 要件定義書：TaskBoard（Trello風タスク管理アプリ）

| 項目 | 内容 |
|---|---|
| アプリ名 | TaskBoard |
| バージョン | v1.1 |
| 作成日 | 2026-09-24 |
| ステータス | 確定（決めたことの一覧は「10. 決定事項」） |
| 作成者 | Fujisawa（Claude Code と作成） |

> 💡 **要件定義書とは**
> 「何を作るか」「どこまで作るか」を、作り始める前に文章で決めておく設計図の最初の1枚。
> ここが曖昧だと、実装中に「これどうするんだっけ？」が大量に発生する。
> AIに実装を頼むときもこの文書を渡せば、指示がブレにくくなる。

---

## 1. 目的・背景

- 自分のタスクを「未着手 → 作業中 → 完了」の流れで見える化し、**今やるべきことを一目で把握**できるようにする。
- 「仕事」と「プライベート」のボードを分けて、タスクが混ざらないようにする。
- 学習目的：上流工程（要件定義 → 設計 → 実装 → テスト → 公開）を一通り体験する。AIエンジニアコース初級編の1作目。

### 1.1 最初の構想と、この文書での扱い

| あなたの構想 | この文書での扱い | 対応する要件 |
|---|---|---|
| ラベルで色分けしたい | 6色から選べるラベル。名前も付けられる。1枚のカードに複数付けられる | F-40〜F-45 |
| ブラウザを閉じても稼働させたい | 「閉じてもデータが残る」という意味（Q1）。変更のたびに自動保存し、開いたら自動で元に戻す | F-50〜F-54 |
| 完了したらドラッグだけでなくチェックも付けたい | カラムの位置とは別に、任意で ✓ を付け外しできる。チェックしてもカードは移動しない（Q2） | F-30〜F-33 |

## 2. 利用者と利用シーン

- **利用者**：自分1人（個人利用）。ログイン・共有機能は持たない。
- **主に使う端末**：PC（スマホは表示が崩れない程度に対応）。
- **利用シーン例**
  1. 朝PCでTaskBoardを開くと、前回見ていた「仕事」ボードが表示される
  2. 今日やるカードを「作業中」へドラッグし、「優先度順」ボタンで並べ直す
  3. 終わったタスクに ✓ を付ける、または「完了」へドラッグする
  4. 上部のタブで「プライベート」ボードに切り替え、買い物リストを確認する
  5. 翌日ブラウザを開き直しても、昨日の状態がそのまま残っている

## 3. 用語の定義

| 用語 | 意味 |
|---|---|
| ボード | カラムが横に並ぶ1枚の板。TaskBoardには「仕事」「プライベート」の2枚がある（名前は変更できる） |
| カラム | ボードの中の縦の列。「未着手」「作業中」「完了」の3つ（Trelloでは「リスト」と呼ぶ） |
| カード | 1つのタスク。カラムの中に縦に並ぶ |
| ラベル | カードに付ける色付きの目印（例：赤＝緊急、青＝クライアントA）。ボードごとに別々に持つ |
| チェック（完了マーク） | カードに付ける ✓。カラムの位置とは別の「終わった」印 |
| D&D | ドラッグ＆ドロップ。マウスでつかんで移動する操作 |
| 整列 | ボタン1つでカラム内のカードを「優先度順」や「期限順」に並べ直すこと |
| localStorage | ブラウザに備わっている保存場所。ブラウザを閉じてもデータが残る |
| MVP | Minimum Viable Product。まず動く最小限の完成形 |

## 4. スコープ（作るもの・作らないもの）

> 💡 最初から全部作ろうとすると完成しない。優先度を4段階（MoSCoW法）で分ける。

| 区分 | 意味 | 主な内容 |
|---|---|---|
| **Must** | 必須（MVP） | 2つのボードの切り替え・名前変更、3カラム表示、カードの追加・編集・削除、D&D、チェック、ラベル、自動保存 |
| **Should** | できれば今回 | 優先度、期限日、整列ボタン、ラベル絞り込み、件数表示、前回のボードを開く、バックアップ（エクスポート・インポート） |
| **Could** | 余裕があれば | カラム追加、期限切れの強調、キーワード検索、タッチ操作、ダークモード、アーカイブ |
| **Won't** | 今回は作らない | ボードの追加・削除、ボード間のカード移動、カード内のチェックリスト、コメント、添付ファイル、繰り返しタスク、操作の取り消し（Undo）、ログイン、複数人での共有、スマホ・別PCとの同期、通知、スマホアプリ、英語表示 |

## 5. 機能要件

> 💡 「ユーザーが何をできるか」の一覧。IDを振っておくと、後で「F-10 を実装して」とAIに指示できる。

### 5.1 ボード・カラム

| ID | 機能 | 優先度 | 詳細 |
|---|---|---|---|
| F-01 | ボード表示 | Must | 選んでいるボードの3カラム（未着手／作業中／完了）を横並びで表示する。初回起動時はどちらのボードも空 |
| F-02 | ボード切り替え | Must | 画面上部のタブで「仕事」「プライベート」を切り替える。カード・ラベルはボードごとに別々 |
| F-03 | ボード名の変更 | Must | タブの名前をダブルクリックして変更する。1〜20文字、空にはできない。初期名は「仕事」「プライベート」 |
| F-04 | 前回のボードを開く | Should | 次に開いたとき、最後に見ていたボードを表示する |
| F-05 | カラムの件数表示 | Should | カラム見出しに件数を出す（例：「作業中 (3)」） |
| F-06 | カラムの追加・名前変更・削除 | Could | MVPは3カラム固定。ただしデータの形は後から追加できるようにしておく |

- ボードは2つで固定。追加・削除はできない（Q5）。

### 5.2 カード

| ID | 機能 | 優先度 | 詳細 |
|---|---|---|---|
| F-10 | カード追加 | Must | 各カラム下の「＋ カードを追加」からタイトルを入力して追加する。Enterで確定、Escでキャンセル |
| F-11 | カード詳細の表示・編集 | Must | カードをクリックするとモーダル（小窓）が開き、タイトル・説明・優先度・期限・ラベルを編集できる。「保存」で反映し、「キャンセル」で破棄する（Q14） |
| F-12 | カード削除 | Must | 詳細モーダルから削除する。誤操作防止のため確認ダイアログを出す |
| F-13 | 優先度 | Should | 高／中／低／なし から選ぶ。カード上に表示 |
| F-14 | 期限日 | Should | カレンダーから日付を選ぶ。カード上に表示 |
| F-15 | 期限切れ・期限当日の強調 | Could | 期限切れは赤、当日は黄色で表示 |

- カードは作ったボードに属する。もう一方のボードへは移動できない（Q13）。間違えたら削除して作り直す。

### 5.3 ドラッグ＆ドロップ・並び替え

| ID | 機能 | 優先度 | 詳細 |
|---|---|---|---|
| F-20 | カラム間の移動 | Must | カードをつかんで、同じボードの別のカラムへ移動する |
| F-21 | カラム内の並び替え | Must | 同じカラムの中で上下の順番を入れ替える |
| F-22 | ドラッグ中の見た目 | Should | つかんだカードに影を付け、落とす位置にガイドを出す |
| F-23 | 整列ボタン | Should | カラム見出しの「⋯」メニューから「優先度順」「期限順」を選ぶと、そのカラムのカードを並べ直す（ルールは下記） |
| F-24 | タッチ操作 | Could | スマホ・タブレットの指でも D&D できる |

**整列のルール（F-23）**

| 整列 | 並ぶ順番 | 同じ値のとき |
|---|---|---|
| 優先度順 | 高 → 中 → 低 → なし | 期限の早い順 |
| 期限順 | 期限の早い順。期限なしは一番下 | 優先度の高い順 |

- 整列は「その場で1回並べ直す」ボタン。並べ直した順番は保存され、そのあとも D&D で自由に動かせる（Q9）。
- チェック済みのカードは、上のルールに関係なく一番下にまとめる（その中の順番は同じルール）（Q15）。

### 5.4 チェック（完了マーク）

| ID | 機能 | 優先度 | 詳細 |
|---|---|---|---|
| F-30 | チェックの付け外し | Must | カード左側の丸いチェックボックスをクリックして切り替える。どのカラムにあっても付けられる |
| F-31 | チェック済みの見た目 | Must | ✓ を表示し、タイトルに取り消し線を引き、カード全体を少し薄くする |
| F-32 | チェックとカラムは連動しない | Must | チェックしてもカードは移動しない。「完了」へ移動してもチェックは自動で付かない（Q2） |
| F-33 | チェック済みカードの一括アーカイブ | Could | ✓ の付いたカードをまとめてボードから片付ける |

### 5.5 ラベル（色分け）

| ID | 機能 | 優先度 | 詳細 |
|---|---|---|---|
| F-40 | ラベルの付け外し | Must | カード詳細でラベルを選ぶ。1枚のカードに複数付けられる（Q3） |
| F-41 | ラベルの色 | Must | 決められた6色（緑・黄・オレンジ・赤・紫・青）から選ぶ |
| F-42 | ラベル名 | Must | ラベルに名前を付けられる（例：赤＝「緊急」）。名前なしでもよい |
| F-43 | ラベルの作成・編集・削除 | Must | ラベル管理画面で、いま開いているボードのラベルを管理する。ラベルを削除すると、付いていたカードからも外れる |
| F-44 | ラベルで絞り込み | Should | ラベルを複数選べ、どれか1つでも付いているカードを表示する（Q16） |
| F-45 | 初期ラベル | Should | 初回起動時、各ボードに6色のラベル（名前なし）を用意しておく |

- ラベルはボードごとに別々に持つ。「仕事」ボードのラベルは「プライベート」ボードには出てこない（Q12）。

### 5.6 データ保存

| ID | 機能 | 優先度 | 詳細 |
|---|---|---|---|
| F-50 | 自動保存 | Must | 変更するたびに自動で localStorage に保存する。保存ボタンは置かない |
| F-51 | 自動復元 | Must | アプリを開いたら前回の状態を復元する（リロード・ブラウザ再起動・PC再起動のあとも） |
| F-52 | 保存失敗の通知 | Must | 容量オーバーなどで保存できなかったら、画面にエラーを表示する |
| F-53 | エクスポート | Should | 2つのボードの全データを JSON ファイルとしてダウンロードする（バックアップ） |
| F-54 | インポート | Should | バックアップファイルから復元する。形式をチェックし、壊れたファイルは読み込まない |

### 5.7 その他

| ID | 機能 | 優先度 | 詳細 |
|---|---|---|---|
| F-60 | キーワード検索 | Could | 開いているボードの中で、タイトル・説明の文字でカードを絞り込む |
| F-61 | ダークモード | Could | 暗い配色に切り替える |

### 5.8 細かい動作ルール

> 💡 実装中に「この場合どうする？」となりやすい細かい動きを、先に決めておく。ここが空いていると、実装後の手直しの原因になる。

**カードの追加・編集**

| ID | 場面 | ルール |
|---|---|---|
| R-01 | 追加する位置 | 新しいカードはカラムの一番下に入る。優先度・期限・ラベル・チェックはすべて「なし」 |
| R-02 | 追加の入力欄 | Enter で確定したあとも入力欄は開いたままで、続けて次のカードを入力できる。Esc か欄の外をクリックで閉じる。空のまま Enter を押しても何も起きない |
| R-03 | カード詳細の保存 | 「保存」で反映。「キャンセル」・×ボタン・Esc で閉じると変更は破棄。小窓の外をクリックしても閉じない（誤操作で消えるのを防ぐ）。タイトルが空のときは「保存」を押せない（Q14） |
| R-04 | 入力の空白 | 前後の空白は取り除いて保存する。空白だけのタイトルは「空」として扱う |
| R-05 | 文字数の上限 | 上限（タイトル100文字・説明1000文字・ラベル名20文字・ボード名20文字）に達したら、それ以上は入力できない |
| R-06 | 説明文 | ただの文章として表示する（改行はそのまま）。太字などの装飾（Markdown）は使えない |

**カードの見た目**

| ID | 場面 | ルール |
|---|---|---|
| R-07 | カードに出す情報 | 上から「ラベル」「チェックボックス＋タイトル」「優先度・期限・説明ありマーク（📝）」。設定していないものは出さない |
| R-08 | ラベルの表示 | 色＋名前で表示する。名前のないラベルは色だけの帯で表示する |
| R-09 | 長いタイトル | 省略せず、折り返して全文を表示する |
| R-10 | 期限日 | 日付だけ（時刻はなし）。過去の日付も選べる。表示は「9/30」、今年以外は「2027/1/15」。あとから消すこともできる |

**チェック・削除**

| ID | 場面 | ルール |
|---|---|---|
| R-11 | チェックの操作 | カードを開かずに付け外しできる。チェックボックスを押しても詳細は開かない |
| R-12 | カードの削除 | 確認ダイアログに「このカードを削除しますか？元に戻せません」と出す。削除したカードは元に戻せない |

**ドラッグ＆ドロップ・整列**

| ID | 場面 | ルール |
|---|---|---|
| R-13 | 空のカラム | カードが1枚もないカラムにもドロップできる |
| R-14 | ドロップ失敗 | カラムの外で手を離したら、カードは元の位置に戻る |
| R-15 | 整列の範囲 | 整列は、メニューを開いたカラムだけに対して行う |

**ラベル・絞り込み**

| ID | 場面 | ルール |
|---|---|---|
| R-16 | ラベルの数 | 1つのボードに最大20個。同じ色で複数作れる（例：赤「緊急」と赤「至急」）。ただし色も名前も同じラベルは作れない |
| R-17 | ラベルの削除 | 確認ダイアログに「このラベルは n 枚のカードから外れます」と出す |
| R-18 | 絞り込みの条件 | 何も選んでいないときは全部表示。複数選んだら、どれか1つでも付いているカードを表示（Q16） |
| R-19 | 絞り込み中にできること | カードの表示・チェック・詳細の編集はできる。D&D・整列・カードの追加はできない（隠れているカードとの順番が決められないため）。絞り込み中であることを画面に表示する |
| R-20 | 絞り込み中の件数 | 「作業中 (2/5)」のように「表示中の枚数／全体の枚数」を出す |
| R-21 | 絞り込みの解除 | ボードを切り替えたとき、リロードしたときに解除する（絞り込み状態は保存しない） |

**ボード**

| ID | 場面 | ルール |
|---|---|---|
| R-22 | ボード名の変更 | ダブルクリックで入力欄になる。Enter で確定、Esc で取り消し。空のまま確定したら元の名前に戻る。もう一方のボードと同じ名前にはできない |

**保存・データ**

| ID | 場面 | ルール |
|---|---|---|
| R-23 | 保存に失敗したとき | 画面上部に赤いメッセージ「保存できませんでした。エクスポートでバックアップしてください」を出す。操作は続けられる |
| R-24 | 保存データが壊れていたとき | 起動時に「データを読み込めませんでした」と出す。壊れたデータは別の場所（`taskboard:broken`）に残してから、空のボードで始める |
| R-25 | 2つのタブで開いたとき | 片方のタブで変更したら、もう片方にも自動で反映する（古い画面の内容で上書きしてデータが消えるのを防ぐ） |
| R-26 | インポート | 今のデータをすべて置き換える（足し合わせはしない）。実行前に「今のデータはすべて置き換わります」と確認する。形式が違う・壊れているファイルは読み込まず、エラーを出す |
| R-27 | エクスポートのファイル名 | `taskboard-backup-YYYY-MM-DD.json`（例：`taskboard-backup-2026-09-24.json`） |
| R-28 | 画面の言葉 | 日本語のみ |

## 6. 画面設計（ざっくり）

### 6.1 画面一覧

| ID | 画面 | 役割 |
|---|---|---|
| S-01 | ボード画面 | メイン画面。ボードの切り替え、カラムとカードの表示、D&D、チェック、整列を行う |
| S-02 | カード詳細モーダル | カードの内容を編集・削除する |
| S-03 | ラベル管理モーダル | 開いているボードのラベルを作成・編集・削除する |

### 6.2 ボード画面のイメージ

```
TaskBoard    [ 仕事 ]  プライベート         [ラベルで絞り込み ▼] [ラベル管理] [バックアップ]
-----------------------------------------------------------------------------------------
 未着手 (2)        ⋯     作業中 (1)        ⋯     完了 (1)          ⋯
+--------------------+  +--------------------+  +--------------------+
| [緊急] [請求]      |  | [学習]             |  | [請求]             |
| ○ 企画書を書く     |  | ○ React入門        |  | ✓ 請求書を送る     |
|   優先:高  〆9/30  |  |   〆10/5           |  |   （取り消し線）   |
+--------------------+  +--------------------+  +--------------------+
+--------------------+
| ○ 資料を印刷       |
+--------------------+
 ＋ カードを追加         ＋ カードを追加         ＋ カードを追加
```

- `[ 仕事 ]` が選択中のボード。`プライベート` をクリックすると切り替わる。名前はダブルクリックで変更できる
- `⋯` はカラムのメニュー。「優先度順」「期限順」の整列はここから行う
- `○` がチェックボックス（クリックで `✓` に切り替わる）
- `[緊急]` などがラベル。実際の画面では色付きで表示する
- 色や余白などの細かい見た目は「画面設計」ステップで決める

## 7. データ設計（保存する情報）

> 💡 何をどんな形で保存するかを先に決めておくと、実装が楽になる。
> ボードが2つあることは、**最初からデータの形に入れておく**。後から足すと作り直しになるため。

### 7.1 全体の形

```
TaskBoard のデータ
├─ schemaVersion : データ形式の版番号（最初は 1）
├─ activeBoardId : 最後に開いていたボードのID
└─ boards（2つ：仕事・プライベート）
    ├─ id / name
    ├─ columns（3つ：未着手・作業中・完了）
    │    └─ cardIds : このカラムのカードID（配列の順番 = 画面の表示順）
    ├─ cards  : このボードのカード
    └─ labels : このボードのラベル
```

### 7.2 ボード

| 項目 | 型 | 内容・ルール |
|---|---|---|
| id | 文字列 | `work`（仕事） / `private`（プライベート）。固定で変わらない |
| name | 文字列 | 表示名。1〜20文字。初期値は「仕事」「プライベート」 |
| columns | カラムの配列 | 3つ（7.3） |
| cards | カードの一覧 | このボードのカード（7.4） |
| labels | ラベルの配列 | このボードのラベル（7.5） |

### 7.3 カラム

| 項目 | 型 | 内容 |
|---|---|---|
| id | 文字列 | `todo`（未着手） / `doing`（作業中） / `done`（完了） |
| title | 文字列 | 表示名 |
| cardIds | 文字列の配列 | このカラムにあるカードのID。**配列の順番＝画面の表示順**。整列ボタンはこの順番を書き換える |

### 7.4 カード

| 項目 | 型 | 必須 | 内容・ルール |
|---|---|---|---|
| id | 文字列 | ○ | カードを見分けるための一意のID（自動で付ける） |
| title | 文字列 | ○ | タイトル。1〜100文字 |
| description | 文字列 | | 説明。0〜1000文字 |
| isCompleted | 真偽値 | ○ | チェックの有無。初期値は false（チェックなし） |
| priority | `high` / `medium` / `low` / なし | | 優先度 |
| dueDate | 日付（YYYY-MM-DD） / なし | | 期限日 |
| labelIds | 文字列の配列 | ○ | 付いているラベルのID一覧。**同じボードのラベルだけ**を指す。初期値は空 |
| createdAt / updatedAt | 日時 | ○ | 作成日時・更新日時 |

### 7.5 ラベル

| 項目 | 型 | 内容 |
|---|---|---|
| id | 文字列 | 一意のID |
| name | 文字列 | ラベル名。0〜20文字 |
| color | `green` / `yellow` / `orange` / `red` / `purple` / `blue` | 色 |

### 7.6 保存形式

- localStorage のキー `taskboard:v1` に、全データを1つの JSON としてまとめて保存する。
- `schemaVersion` は、将来データの形を変えたとき、古いデータを新しい形に移し替えるための目印になる。

## 8. 非機能要件

> 💡 「機能」以外の品質の約束。速さ・使える環境・安全性など。

| ID | 分類 | 要件 |
|---|---|---|
| N-01 | 保存 | ブラウザを閉じても、リロードしても、PCを再起動しても、データが残る |
| N-02 | 保存の注意点 | データは「このPCのこのブラウザ」の中だけにある。別のブラウザ・スマホ・シークレットモードからは見えない。ブラウザの閲覧データを削除すると消える → F-53 のバックアップで備える |
| N-03 | 公開時のプライバシー | Vercel で公開しても、データは使う人それぞれのブラウザにしか保存されない。URLを知っている人がいても、自分のタスクは見られない |
| N-04 | 対応ブラウザ | Chrome 最新版（必須）。Edge・Safari 最新版（できれば） |
| N-05 | 画面サイズ | PC（幅1280px）を基準にする。スマホ幅（375px）でも崩れず、横スクロールでカラムを見られる |
| N-06 | 性能 | ボード1つにカード200枚あっても、表示・D&D がもたつかない。起動から表示まで2秒以内（目安） |
| N-07 | 使いやすさ | 主な操作（追加・移動・チェック・ボード切り替え）はクリック1〜2回で終わる |
| N-08 | アクセシビリティ | ラベルは色だけでなく名前も表示する（色の見分けが苦手な人への配慮）。チェックボックスはキーボードでも操作できる |
| N-09 | セキュリティ | 入力された文字はただの文字として表示し、HTMLとして実行しない（XSS対策）。インポート時はファイルの中身を検証する |
| N-10 | 入力チェック | タイトル・ボード名が空のものは保存しない。文字数の上限を超える入力は受け付けない |
| N-11 | 品質 | 自動テストを書き、カバレッジ（テストで実行されたコードの割合）80%以上を目指す |
| N-12 | 費用 | 0円。サーバーやデータベースは使わない。公開は Vercel の無料枠を使う |

## 9. 技術構成

> コースでの技術指定はないため（Q8）、この構成で進める。

| 役割 | 使うもの | 選ぶ理由 |
|---|---|---|
| 言語 | TypeScript | 型のおかげでミスに早く気づける。AIとの相性も良い |
| 画面（UI） | React | 利用者が多く、調べれば情報がすぐ見つかる |
| 開発ツール | Vite | 設定が少なく、起動が速い |
| 見た目 | Tailwind CSS | クラス名を書くだけで見た目を整えられる |
| D&D | dnd-kit または Pragmatic drag and drop（Trelloの運営元 Atlassian 製） | 環境構築のときに比べて決める |
| 保存 | localStorage | サーバー不要で、ブラウザだけで完結する |
| テスト | Vitest + React Testing Library（部品単位）、Playwright（画面操作） | 単体テストと E2E テストの定番 |
| 公開 | Vercel | 無料で URL を発行して公開できる（Q7） |

> ライブラリのバージョンや使い方は、環境構築のときに公式ドキュメントで最新情報を確認する。

## 10. 決定事項

> 💡 要件定義で出た質問と、その答え。後から「なぜこうしたんだっけ？」となったときに見返す場所。

| No | 質問 | 決定 | 理由 |
|---|---|---|---|
| Q1 | 「ブラウザを閉じても稼働」とは、どれのこと？ | 閉じてもデータが残る | スマホ・別PCとの同期や、閉じている間の通知はサーバーとログインが必要で難易度が大きく上がる。次の作品以降で挑戦する |
| Q2 | チェックとカラムを連動させる？ | 連動しない | 動きが予想しやすく、「作業中だけど実は終わった」状態も表せる |
| Q3 | 1枚のカードにラベルを何個付けられる？ | 複数 | Trello と同じ使い方ができる |
| Q4 | カラムは3つ固定でよい？ | MVP は固定 | カラム追加は Could として後から入れる |
| Q5 | ボードはいくつ？ | 2つで固定 | 仕事とプライベートを分けたい。追加・削除まで作ると作業量が大きく増えるため固定にする |
| Q6 | 主に使う端末は？ | PC 優先 | スマホは表示が崩れない程度に対応する |
| Q7 | 完成したらネットに公開する？ | Vercel で公開 | ポートフォリオとして見せられる |
| Q8 | コースで指定されている技術はある？ | なし | 9章の構成で進める |
| Q9 | カラム内の並び順はどう決める？ | D&D ＋ 整列ボタン | 普段は手で自由に並べ、必要なときだけ優先度順・期限順に一発で並べ直せる |
| Q10 | アプリ名は？ | TaskBoard | シンプルで何のアプリか分かりやすい |
| Q11 | ボード名は変えられる？ | 変更できる | 「勉強」「副業」など、使い方に合わせて名前を付けられる |
| Q12 | ラベルは2つのボードで共通？ | ボードごとに別 | 仕事とプライベートでは必要なラベルが違う（Trelloと同じ） |
| Q13 | カードを別のボードへ移動できる？ | 今回は移動できない | 1作目は機能をしぼる。間違えたら削除して作り直す |
| Q14 | カード詳細の編集内容はどう保存する？ | 保存ボタン | 「キャンセル」で元に戻せて、動きが分かりやすい。実装もシンプル |
| Q15 | 整列のとき、チェック済みのカードはどこに並べる？ | 一番下にまとめる | 終わっていないカードが上に来て、今やるべきことが見やすい |
| Q16 | ラベルの絞り込みはいくつ選べる？ | 複数・どれかが付いている | 「緊急」と「請求」のように、関係するカードをまとめて見られる |
| Q17 | カードの中のチェックリストは必要？ | 今回は作らない | 1作目は機能をしぼる。細かい作業は説明欄に書く。2作目以降の追加機能の候補 |

> 5.8「細かい動作ルール」の R-01〜R-28 は、一般的なアプリの動きに合わせてこちらで決めたもの。違和感があれば変更する。

## 11. 受け入れ条件（完成の判定基準）

> 💡 「何ができたら完成か」を具体的に書く。後でテストを書くときの元ネタになる。

| ID | 確認すること | 手順 | 期待する結果 |
|---|---|---|---|
| AC-01 | 保存 | カードを3枚追加 → ブラウザを完全に閉じて開き直す | 3枚とも同じボード・同じカラム・同じ順番で表示される |
| AC-02 | ボード切り替え | 「仕事」にカードAを追加 → 「プライベート」に切り替える | 「プライベート」にはカードAが表示されない。「仕事」に戻すとカードAがある |
| AC-03 | ボード名の変更 | 「プライベート」を「勉強」に変更 → リロード / 名前を空にして確定 | 変更後はリロードしても「勉強」のまま。空の名前では確定できず、元の名前に戻る |
| AC-04 | D&D | 「未着手」のカードを「作業中」の2番目にドラッグ → リロード | 作業中の2番目に表示され、リロード後もそのまま |
| AC-05 | 整列 | 優先度「低・高（チェック済み）・なし・中」のカードが並ぶカラムで「優先度順」を選ぶ → 1枚を D&D で一番上へ動かす | 「中・低・なし・高（チェック済み）」の順に並ぶ。そのあと D&D で自由に動かせる |
| AC-06 | チェック | 「作業中」のカードの ○ をクリック → もう一度クリック | 1回目：✓・取り消し線が付き、カードは作業中のまま。2回目：元に戻る |
| AC-07 | ラベル | 「仕事」で赤のラベル「緊急」をカードに付ける → 「プライベート」のラベル一覧を見る → 「仕事」のラベル管理で「緊急」を削除 | 「緊急」は仕事のカードに赤く表示され、プライベートの一覧には出てこない。削除後はカードからも消える |
| AC-08 | 入力チェック | タイトルを空のまま「追加」 | カードは追加されない |
| AC-09 | 削除 | カードを削除 → 確認ダイアログでキャンセル／OK | キャンセルなら残り、OK なら消える |
| AC-10 | バックアップ | エクスポート → 両方のボードのカードを全部消す → インポート | 2つのボードとも、エクスポートした時点の状態に戻る |
| AC-11 | 詳細のキャンセル | カード詳細でタイトルを書き換える → 「キャンセル」 | カードのタイトルは書き換える前のまま |
| AC-12 | 絞り込み | 「緊急」「請求」の2つを選んで絞り込む | どちらかが付いたカードだけ表示され、件数は「表示中／全体」になる。D&D・整列・追加はできない |
| AC-13 | 2つのタブ | 同じアプリを2つのタブで開く → 片方でカードを追加 → もう片方を見る | もう片方にも追加したカードが表示される |
| AC-14 | 壊れたデータ | localStorage の保存データを壊れた文字に書き換えてリロード | エラーメッセージが出て、空のボードで起動する。アプリは止まらない |
