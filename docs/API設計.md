## 1. 共通の決まり

- URL は `/api` で始まる。開発中のあて先は `http://127.0.0.1:8080`。画面からは、Vite の中継（proxy）を通して `/api/...` で呼ぶ（[技術スタック](技術スタック.md) の2章）。
- やりとりは JSON（文字コードは UTF-8）。
- ボードごとのものは、URL もボードの下に置く（例：`/api/boards/{boardId}/tasks`）。タスク1件のように番号だけで決まるものは、短い URL にする（例：`/api/tasks/{taskId}`）。

### 1.1 返事の共通の包み

成功でも失敗でも、次の4つの項目で返す。

| 項目 | 成功のとき | 失敗のとき |
|---|---|---|
| `success` | `true` | `false` |
| `data` | 返すデータ | `null` |
| `error` | `null` | `{ "code": "…", "message": "…" }` |
| `meta` | 今は使わず `null` | `null` |

### 1.2 値の書き方

| 項目 | 書き方 |
|---|---|
| `status`（カラム） | `"todo"`（未着手）・`"doing"`（作業中）・`"done"`（完了） |
| `priority`（優先度） | `"high"`・`"medium"`・`"low"`。なしは `null` |
| `color`（ラベルの色） | `"green"`・`"yellow"`・`"orange"`・`"red"`・`"purple"`・`"blue"` |
| `dueDate`（期限日） | `"2026-11-10"` の形の文字列（時刻なし）。なしは `null` |
| `description`（説明） | 文字列。なしは `null` |
| ラベルの `name` | 文字列。名前なしは `""`（空の文字） |

### 1.3 エラーのとき

画面には分かりやすい日本語だけを出し、SQL やプログラムの内部情報は出さない。詳しい内容はサーバーのログにだけ残す（N-17）。

| 場面 | 状態コード | `error.code` | `error.message` |
|---|---|---|---|
| タスクがない | 404 | `TASK_NOT_FOUND` | タスクが見つかりません |
| ボードがない | 404 | `BOARD_NOT_FOUND` | ボードが見つかりません |
| URL の番号が数字でない | 400 | `INVALID_ID` | 番号の形が正しくありません |
| ない URL | 404 | `NOT_FOUND` | 指定された URL は見つかりません |
| その URL で使えないメソッド | 405 | `METHOD_NOT_ALLOWED` | この URL では使えない操作です |
| 予想外のエラー | 500 | `INTERNAL_ERROR` | サーバーでエラーが起きました |

## 2. API の一覧

| メソッド | URL | すること | 関係する機能 |
|---|---|---|---|
| GET | `/api/boards` | ボードの一覧 | F-01・F-02 |
| GET | `/api/boards/{boardId}/tasks` | 1つのボードのタスク全件（ラベル付き） | F-01・F-51 |
| GET | `/api/tasks/{taskId}` | タスク1件（ラベル付き） | F-11 |

## 3. それぞれの API

### 3.1 GET `/api/boards`：ボードの一覧

- タブの並び順（`position` の小さい順）で返す。

```json
{ "success": true,
  "data": [ { "id": 1, "name": "仕事", "position": 0 },
            { "id": 2, "name": "プライベート", "position": 1 } ],
  "error": null, "meta": null }
```

### 3.2 GET `/api/boards/{boardId}/tasks`：1つのボードのタスク全件

- 並び順：**未着手 → 作業中 → 完了**の順。同じカラムの中は `position` の小さい順。
- ラベルは、タスクごとに番号の小さい順。
- ボードはあるがタスクが0件のときは、エラーにせず `"data": []` を返す。
- ボードがないときは 404（`BOARD_NOT_FOUND`）。

```json
{ "success": true,
  "data": [ { "id": 1, "boardId": 1, "status": "todo", "position": 0,
              "title": "経費の精算を出す", "description": null,
              "completed": false, "priority": "high", "dueDate": "2026-11-07",
              "labels": [ { "id": 1, "name": "緊急", "color": "red" },
                          { "id": 2, "name": "請求", "color": "yellow" } ] } ],
  "error": null, "meta": null }
```

| 項目 | 中身 |
|---|---|
| `id` | タスクの番号 |
| `boardId` | 所属するボードの番号 |
| `status` | どのカラムにあるか（1.2） |
| `position` | カラムの中の表示順（0 から） |
| `title` | タイトル |
| `description` | 説明（なしは `null`） |
| `completed` | 完了マーク（✓）の有無 |
| `priority` | 優先度（なしは `null`） |
| `dueDate` | 期限日（なしは `null`） |
| `labels` | 付いているラベル（`id`・`name`・`color`）の一覧 |

### 3.3 GET `/api/tasks/{taskId}`：タスク1件

- `data` に、3.2 と同じ形のタスクを1つ入れて返す。
- タスクがないときは 404（`TASK_NOT_FOUND`）。番号が数字でないときは 400（`INVALID_ID`）。

```json
{ "success": false, "data": null,
  "error": { "code": "TASK_NOT_FOUND", "message": "タスクが見つかりません" },
  "meta": null }
```

## 4. 見本データ

- 中身は [DB設計](DB設計.md) の「4. 見本データ」どおり（ボード2・ラベル12・タスク10）。プログラムでは `SampleDataService` の1か所にまとめている。
- APIサーバーが起動したとき、**ボードのテーブルが空のときだけ**入れる。ボードが1つでもあれば入れない。
- 期限は「日本時間の今日」から数えた日付で入れる（例：昨日・今日・3日後）。
- データを消して見本データに戻す処理（毎日のリセット、F-55）は、まだ作っていない。
