## 2. 版の決め方と更新の方針

### 2.1 `package.json` の記号の意味

| 書き方 | 例 | 意味 |
|---|---|---|
| `^`（キャレット） | `"react": "^19.3.1"` | 19.x.x の中で新しい版に上げてよい（大きな版は上げない） |
| `~`（チルダ） | `"typescript": "~6.0.3"` | 6.0.x の中だけで上げてよい（6.1 には上げない） |

- 実際に入る版は `package-lock.json` が決める。`npm ci` を使えば、誰の PC でも同じ版が入る。
- 🔼 の小さな更新（例：TanStack Query 5.107 → 5.108）は、まとめて上げてよい。上げたら `npm run lint`・`npm run build`・`npm test` が通ることを確かめる。

### 2.2 TypeScript を 6.0 にとどめる理由

- TypeScript 7 は、中身が大きく作り直された大きな版の変更。
- 書き方の点検に使う **typescript-eslint（8.73.0）が、TypeScript 6.1 未満にしか対応していない**。7 に上げると `npm run lint` が動かなくなる。
- そのため `~6.0.3` と書いて、6.0 系から出ないようにしている。typescript-eslint が 7 に対応したら上げる。

## 3. フォルダ構成（`frontend/`）

```
frontend/
├─ index.html             画面の入口（React がここに画面を描く）
├─ package.json           使う部品と npm のコマンド
├─ package-lock.json      実際に入る部品の版（自動で作られる。手で書き換えない）
├─ vite.config.ts         開発サーバー（5173番）、API への中継、テストの設定
├─ tsconfig*.json         TypeScript の設定（strict：型のチェックを厳しくする）
├─ eslint.config.js       書き方の点検（ESLint）の設定
├─ .prettierrc.json       見た目をそろえる（Prettier）の設定
└─ src/
    ├─ main.tsx           起動の入口。TanStack Query の準備をして App を表示する
    ├─ App.tsx            画面全体（公開デモの案内 ＋ ボード画面）
    ├─ index.css          Tailwind の読み込みと色の決まり（モックと同じ色）
    ├─ api/               サーバーとのやりとり
    │   ├─ client.ts        fetch で API を呼び、失敗を「接続できない」「サーバーのエラー」に分ける
    │   ├─ queries.ts       ボード一覧・タスク一覧を読む（TanStack Query）
    │   ├─ queryClient.ts   やり直しの回数・タブに戻ったら読み直す、の設定
    │   └─ schemas.ts       届いたデータの形（Zod）
    ├─ features/board/    ボード画面（S-01）の部品：タブ・カラム・カード・ラベル
    ├─ components/        共通の部品：公開デモの案内、読み込み中・エラーの表示
    ├─ lib/               小さな道具：決まった値、期限の表示、カラムへの振り分け
    └─ test/              テスト用の部品：見本データ、作り物の API（MSW）
```

- テストのファイルは、テストする部品のとなりに `〇〇.test.ts(x)` の名前で置く。
- `node_modules/`（入れた部品）・`dist/`（ビルドの結果）・`coverage/`（カバレッジの結果）は自動で作られるので、GitHub に上げない（`frontend/.gitignore`）。

## 4. 主な設定

| 設定 | 場所 | 内容 |
|---|---|---|
| ポート | `vite.config.ts` | 画面は **5173 番だけ**で動かす。使われていたら別の番号に逃げずに止まる（`strictPort`、[CLAUDE.md](../../CLAUDE.md) のルール6） |
| API への中継 | `vite.config.ts` | `/api` で始まる依頼を `http://127.0.0.1:8080`（APIサーバー）へ送る。開発中は CORS の設定がいらない（[技術スタック](../技術スタック.md) の2章） |
| 型のチェック | `tsconfig.app.json` | `strict`（厳しいチェック）、使っていない変数や引数をエラーにする |
| カバレッジの基準 | `vite.config.ts` | 行・関数・分岐・文のすべてで **80% 以上**（N-27）。下回ると `npm run coverage` が失敗する |

## 5. npm のコマンド

`frontend/` の中で実行する。

| コマンド | すること |
|---|---|
| `npm ci` | `package-lock.json` どおりに部品を入れる（最初の1回と、部品が変わったとき） |
| `npm run dev` | 開発サーバーを起動する → http://localhost:5173 |
| `npm run build` | 型のチェックをしてから、公開用のファイルを `dist/` に作る |
| `npm run preview` | `dist/` を手元で表示して確かめる |
| `npm run lint` | 書き方の点検（ESLint） |
| `npm run format` | 見た目をそろえる（Prettier）。`format:check` は確かめるだけ |
| `npm test` | テストを1回実行する（`test:watch` は保存のたびに実行） |
| `npm run coverage` | テストを実行して、カバレッジを測る |

- サーバーを起動するときは、決まったポートで起動する手順（`.claude/skills/start-servers/SKILL.md`）にしたがう。

## 6. 気をつけること

- **期限日は文字列のまま扱う**：`new Date("2026-10-31")` は時差で1日ずれることがあるので使わない（[技術スタック](../技術スタック.md) の7章）。
- **`VITE_` で始まる環境変数は誰でも見られる**：画面のプログラムに埋め込まれるため、秘密は入れない（[技術スタック](../技術スタック.md) の6章）。
- **サーバーのデータは TanStack Query で持つ**：自分で `useState` にコピーしない。読み直しや失敗の扱いがそろう。
- **届いたデータは Zod で確かめてから使う**：形が違ったら「サーバーから届いたデータの形が正しくありません」と出す。
