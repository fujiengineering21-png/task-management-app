## 1. 使っている技術

### 1.1 土台

| 役割 | 技術 | 決めた版 | 入っている版 | 最新版 | 選んだ理由 |
|---|---|---|---|---|---|
| 言語 | Java（Homebrew の OpenJDK） | 25（LTS） | 25.0.5 | LTS の最新：25 ✅（いちばん新しいのは 27） | コースの指定。いちばん新しい長期サポート版（LTS、2030年9月まで）。27 は半年でサポートが終わる短期版なので選ばない |
| フレームワーク | Spring Boot | 4.1 系 | 4.1.2 | 4.1.2 ✅（4.2 は試験版） | コースの指定。いちばん新しい安定版で、無料サポートは2027年7月まで |
| ビルド | Gradle（Groovy で書く。Gradle Wrapper を使う） | 9 系 | 9.8.2 | 9.9.1 🔼 | コースの推奨。Wrapper（`./gradlew`）なので、Gradle 本体を別に入れなくてよい |
| 部品の版の管理 | io.spring.dependency-management | Boot に合わせる | 1.1.7 | 1.1.7 ✅ | Spring Boot が動作を確かめた組み合わせの版を、自動で選んでくれる |

- Gradle の版は `backend/gradle/wrapper/gradle-wrapper.properties` に書いてある。`./gradlew` を初めて実行したときに、その版（9.8.2）が `~/.gradle/wrapper/dists/` にダウンロードされる（この PC にはダウンロード済み）。
- 版の確かめ方：`java -version`、`backend/` で `./gradlew --version`（Gradle と、使っている Java の版が出る）。Gradle を上げるときは `./gradlew wrapper --gradle-version 9.9.1` のように実行する。

### 1.2 使っている部品（Spring Boot が版を決める）

下の部品は `build.gradle` に版を書かない。Spring Boot 4.1.2 が決めた版が自動で使われる。

| 役割 | 部品（`build.gradle` の名前） | 中身と版 | 選んだ理由 |
|---|---|---|---|
| Web（API） | `spring-boot-starter-webmvc` | Spring Framework 7.0.10・Tomcat 11.0.27・Jackson 3.1.7 | REST API を作る標準の部品。JSON の変換は Jackson 3 |
| DB の読み書き | `spring-boot-starter-data-jpa` | Hibernate 7.4.13 | 表を Java のクラスとして扱え、簡単な読み書きは SQL を書かずに済む。教材が多い（Q25） |
| マイグレーション | `spring-boot-starter-flyway` ＋ `flyway-database-postgresql` | Flyway 12.4.0 | テーブルの作成・変更を SQL ファイルで管理し、何度でも同じ手順で作り直せる（N-28） |
| DB のドライバ | `org.postgresql:postgresql` | 42.7.14 | PostgreSQL につなぐための部品 |
| 動作確認 | `spring-boot-starter-actuator` | Boot に合わせる | 「起動したか」「データベースにつながっているか」を `/actuator/health` で確かめる。公開するのは health だけ |
| テスト | `spring-boot-starter-webmvc-test` | JUnit Jupiter 6.0.3・Mockito 5.23.0・AssertJ 3.27.7 | 詳しくは [開発ツール](開発ツール.md) |

### 1.3 これから入れる部品

| 役割 | 部品 | 最新版 | 入れるとき |
|---|---|---|---|
| 入力チェック | `spring-boot-starter-validation`（Bean Validation） | Boot に合わせる | 作成・更新の API を作るとき（N-12） |
| API の説明書 | springdoc-openapi（Swagger UI） | 3.2.0（3.2 系が Boot 4.1 に対応） | API の一覧をブラウザで見て、その場で試したくなったとき |
| 書き込みの回数制限 | Bucket4j | 8.22.0 | 書き込みの API を作るとき（1分に60回まで、N-13）。10KB の制限は自作のフィルタで行う |
| カバレッジ | JaCoCo | 0.8.16（0.8.14 以上が Java 25 に対応） | テストのカバレッジを測るとき（N-27）。[開発ツール](開発ツール.md) |

## 2. フォルダ構成（`backend/`）

```
backend/
├─ build.gradle・settings.gradle   ビルドの設定（使う部品と Java の版）
├─ gradlew・gradle/wrapper/        Gradle Wrapper（決まった版の Gradle を自動で用意する）
└─ src/
    ├─ main/
    │   ├─ java/com/taskboard/
    │   │   ├─ TaskBoardApplication.java  起動クラス
    │   │   ├─ controller/   API の入口（URL ごとの受け付け）と、エラーを日本語の返事に変える部品
    │   │   ├─ service/      ルールと判断（R-xx の処理）。見本データ（SampleDataService）もここ
    │   │   ├─ repository/   データベースの読み書き（Spring Data JPA）
    │   │   ├─ entity/       テーブルに対応するクラスと、値の変換（AttributeConverter）
    │   │   ├─ dto/          API でやりとりするデータの形（record）と、返事の共通の形
    │   │   └─ config/       時計（日本時間）・起動時の見本データ投入
    │   └─ resources/
    │       ├─ application.properties   設定（サーバーの待ち受け場所、データベースの接続）
    │       └─ db/migration/            Flyway の SQL ファイル（V1__create_tables.sql）
    └─ test/java/com/taskboard/        テスト（main と同じフォルダ分け）
```

- 呼び出しの向きは **controller → service → repository** の一方通行にする。画面に近い側が、データに近い側を呼ぶ。
- 今ある API は読み取りだけ（`GET /api/boards`・`GET /api/boards/{boardId}/tasks`・`GET /api/tasks/{taskId}`）。詳しくは [API設計](../API設計.md)。

## 3. 主な設定（`application.properties`）

| 設定 | 値 | 意味 |
|---|---|---|
| `server.address` | `127.0.0.1` | この PC の中からの接続だけを受け付ける。同じ Wi-Fi の他の機器からは開けない。公開先では環境変数 `SERVER_ADDRESS=0.0.0.0` で上書きする |
| ポート | 8080（初期値のまま） | 番号は変えない（[CLAUDE.md](../../CLAUDE.md) のルール6） |
| `spring.config.import` | `../.env`・`.env` | データベースの接続情報を、リポジトリ直下の `.env` から読む |
| `spring.datasource.*` | `.env` の値 | 接続先は Docker の PostgreSQL（[データベース](データベース.md)）。初期値を書かないのは、別のデータベースへ誤ってつながないため |
| `spring.jpa.hibernate.ddl-auto` | `validate` | テーブルは Flyway が作る。JPA は形が合っているかを確かめるだけ |
| `spring.jpa.open-in-view` | `false` | 画面を返すまでデータベースの接続を持ち続けない（メモリと接続数の節約） |

## 4. Gradle のコマンド

`backend/` の中で実行する。初回は Gradle 本体のダウンロードに時間がかかる。

| コマンド | すること |
|---|---|
| `./gradlew bootRun` | APIサーバーを起動する → http://localhost:8080（先にデータベースを起動しておく） |
| `./gradlew test` | テストを実行する（結果は `build/reports/tests/test/index.html`） |
| `./gradlew build` | テストを実行して、動かせる形（jar）を `build/libs/` に作る |

- 動いているかの確認：http://localhost:8080/actuator/health を開いて `{"status":"UP"}` が出れば正常。
- サーバーを起動するときは、決まったポートで起動する手順（`.claude/skills/start-servers/SKILL.md`）にしたがう。

## 5. 実装で気をつけること

- **Boot 4 との違い**：Web の部品は `spring-boot-starter-webmvc`、Flyway は `spring-boot-starter-flyway` が必要など、Boot 3 から名前や設定が変わっている。JSON の変換には Jackson 3 を使う。古い記事どおりに書いて動かないときは、公式ドキュメントで確かめる。
- **値の変換**：`status`・`priority`・`color` は小文字の値（`todo` など）で保存する。Java の enum とは、変換の部品（AttributeConverter）でつなぐ。`boards.position`（SMALLINT）は Java の `Short` で受ける。
- **並び替えはまとめて1回**：D&D と整列は、移動元と移動先の順番（`position`）を1つのトランザクションで振り直す（UC-04）。
- **まとめて読む**：ボードを開くときは、タスクとラベルをまとめて読み、1件ずつ何度も問い合わせない（N+1 問題を避ける）。
- **見本データ**：Flyway には入れず、Java の1つの部品（SampleDataService）にまとめる。初回起動と毎日のリセット（F-55）で同じものを使う。
- **エラーの返し方**：内部の情報を出さず、決まった形と日本語のメッセージで返す（N-17、[API設計](../API設計.md)）。
- **使わないもの**：Spring Security・Lombok・`@Scheduled`・`spring-boot-docker-compose`（理由は [技術スタック](../技術スタック.md) の9章）。
